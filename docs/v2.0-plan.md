# NATS Client 2.0 版本规划

## 版本目标

将 NATS Client 从基础功能完备的 1.0 版本，升级为功能完善、体验优秀、安全可靠的现代化 NATS 桌面客户端。

---

## 第一阶段：修复与优化 (P0)

> 目标：修复已知缺陷，提升安全性和稳定性

### 1.1 功能缺陷修复

| 任务 | 文件 | 描述 | 状态 |
|-----|------|------|------|
| 修复 Reply Service 动态更新 | NatsService.ts | `updateReplyPayload` 方法需要正确实现动态更新响应内容 | ⬜ |
| 修复 JetStream ACK/NAK | JetStreamPanel.tsx | 记录消息来源的 consumer，避免操作错误的 consumer | ⬜ |
| 移除调试代码 | main.tsx | 删除 `console.log` 和未使用的 `window.ipcRenderer` | ⬜ |

### 1.2 安全性改进

| 任务 | 文件 | 描述 | 状态 |
|-----|------|------|------|
| 密码加密存储 | StorageService.ts | 使用 electron safeStorage 加密敏感信息 | ⬜ |
| 敏感信息脱敏显示 | ConnectionList.tsx | 密码/Token 显示为 **** | ⬜ |

### 1.3 错误处理改进

| 任务 | 文件 | 描述 | 状态 |
|-----|------|------|------|
| 移除空 catch 块 | NatsService.ts | 向用户显示错误提示而非静默忽略 | ⬜ |
| 添加错误边界 | components/ | 创建 ErrorBoundary 组件防止应用崩溃 | ⬜ |
| 统一错误提示机制 | stores/ | 创建统一的错误处理和提示系统 | ⬜ |

### 1.4 代码质量

| 任务 | 文件 | 描述 | 状态 |
|-----|------|------|------|
| 移除 any 类型 | NatsService.ts | 使用正确的类型定义 | ⬜ |
| 统一 IPC 通道常量 | preload.ts, ipc/index.ts | 提取到共享常量文件 | ⬜ |

## 开发规范

### 代码规范
- 所有新代码必须有 TypeScript 类型定义
- 禁止使用 any 类型
- 所有错误必须正确处理并向用户展示
- 新功能必须添加到设置系统（如有配置项）

### 测试规范
- 核心功能需要手动测试
- 修复 Bug 需要验证修复效果
- 发布前进行完整功能回归测试

### 文档规范
- 新功能需要更新 README.md
- API 变更需要更新类型定义注释
- 发布时更新 CHANGELOG
